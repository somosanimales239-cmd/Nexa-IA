# Nexa AI v1.8.2 — Visual Review Timeout Fix

## Problema corregido
Cuando Nexa generaba una imagen y luego Qwen2.5-VL:3b la revisaba, el proceso completo podía superar el límite fijo de **6 minutos**. Eso provocaba que el pipeline completo se detuviera incluso cuando ComfyUI y Qwen seguían trabajando correctamente.

## Objetivo de v1.8.2
Separar el **timeout por intento** del **timeout total del pipeline**.

## Nuevo comportamiento
- **Render timeout por intento:** 6 minutos.
- **Review timeout por intento:** 2 minutos.
- **Budget total del pipeline visual:** 18 minutos por defecto.
- **Intentos máximos:** 3.
- Si el intento 1 falla la revisión visual, Nexa puede seguir con intento 2 y 3 sin matar todo el pipeline a los 6 minutos.
- Si hay progreso/heartbeat reciente, Nexa extiende el margen de espera.
- Si Qwen devuelve errores críticos (por ejemplo E002 / E008), Nexa repara el prompt y reintenta.
- Si no hay progreso real durante demasiado tiempo, Nexa sí aborta de forma controlada.

## Señales esperadas en UI
- Renderizando intento 1/3…
- Revisando imagen con Qwen 1/3…
- Reparando prompt…
- Renderizando intento 2/3…
- Revisando imagen con Qwen 2/3…
- Nexa Visual aprobó la imagen · 92/100

## Cambio importante
El timeout de 6 minutos ya no debe matar todo el trabajo visual completo. Solo se aplica a un intento individual, y el pipeline total tiene un presupuesto mayor.

## Recomendación inicial
- `maxVisualAttempts = 3`
- `perAttemptRenderTimeoutMs = 360000`
- `perAttemptReviewTimeoutMs = 120000`
- `totalVisualPipelineTimeoutMs = 1080000`
- `progressGraceMs = 120000`

## Nota
Este paquete está pensado como hotfix para el flujo de revisión visual. Si tu App Builder usa un archivo `main-v181.js` como entrypoint, la siguiente versión sugerida es `main-v182.js`.
